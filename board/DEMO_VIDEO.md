# 演示视频：分镜与录制脚本

> 目标：3 分钟以内，**一镜到底**最好，两段拼接也可以。评委要看的是「这块板真的在算、
> 算出来的东西真的是对的」，不是剪辑。所以每个镜头里出现的数字都要能在仓库档案里找到对应行。
>
> 录制日期建议：不晚于 **2026-11-03**，给上传留一天余量。

## 0. 录制前的一次性准备（录之前做掉，不要录进画面）

```powershell
# 1. 板子已按 board/README.md 烧好 BOOT.BIN（SD 卡启动跳线），串口线插好
powershell -ExecutionPolicy Bypass -File board\baremetal\bm_ports.ps1
$env:BM_PORT = 'COM?'          # 换成 bm_ports.ps1 报出来的那个，别用蓝牙虚拟口

# 2. 先用一次冷启动确认板子活着（这一遍不用录）
powershell -ExecutionPolicy Bypass -File board\baremetal\bm_capture_cold.ps1 -Seconds 45
```

准备清单：

- [ ] 屏幕上只留三个窗口：串口终端（放最大）、`board\baremetal\logs\` 文件夹、一个投影/PPT 窗口（可选）
- [ ] 串口终端字号调到 **画面里能看清 20.790 这个数**（这是全片最重要的一帧）
- [ ] 关掉通知弹窗、关掉微信
- [ ] 手机/相机固定，横屏 1080p，别手持
- [ ] 桌面背景换成纯色（录出来的字更清楚）

## 2. 一键录制命令（第二遍用这个，比手敲稳）

```powershell
$env:BM_PORT = 'COM7'

# 全片主体：3 轮逐位 + 50 次计时，最后自动写 repeat.json
powershell -ExecutionPolicy Bypass -File board\baremetal\bm_repeat.ps1 -NumRounds 3 -Timing 50
```

跑完会得到：

```
board\baremetal\logs\bm_repeat_<时间戳>.txt    原始串口全文（录屏里出现的每一行都在这里）
board\repeat.json                             解析后的结果 + 计时统计
```

这两个文件**不要改**，录完直接随提交一起上传；它们是「视频里说的数是真的」的凭据。

## 3. 两个必须讲清楚、不能含糊的地方

### 3.1 速度对比的方向（这一条最容易说反）

`metrics/cpu_baseline.csv` 里，同一块板、同一条 492 字指令流、同一份数据：

- Cortex-A9 @650 MHz：**7.470 ms**
- PL @100 MHz：**20.790 ms**

所以 **CPU 比 PL 快 2.78×**。PL 每拍干的活是 A9 的 2.33 倍，但时钟低 6.5 倍，净输。
视频里**绝对不要**说「PL 比 CPU 快 2.78 倍」——那是把方向说反了，而且评委一问就穿。

正确说法：

> 「我们还做了同板 CPU 基线：同样的指令流，A9 上 7.470 ms，PL 上 20.790 ms，
> **CPU 反而快 2.78 倍**。PL 每拍效率高 2.33 倍，但跑在 100 MHz，输在时钟上。
> 这条基线告诉我们瓶颈是累加器链和每拍 MAC 数，不是 DSP 不够。
> 报告 §5.4 把这个负结果原样写进去了。」

主动说出这个负结果，比藏起来强得多——它证明作者真的测过、没有编数。

如果时间紧，**就跳过这一镜**。少一镜不会扣分，说反一个数会。

### 3.2 准确率（这一条不要说高）

准确率 0.34–0.40，三类 chance 是 33.3%。**不要**在视频里说「识别情绪」。
正确说法：「它实时输出一个三分类预测；在留出被试上的准确率接近随机，
我们把它当作**平台能力演示**，不当作识别结果。」——这句话说出来比任何数字都加分。

## 4. 不录的东西

| 不要录 | 原因 |
|---|---|
| Vivado 综合/实现全过程 | 十几分钟，没有信息量；可复现性用 `BITSTREAM_MANIFEST.md` 证明，不用录屏 |

| 真实传感器接线 | 四路都是 AFFEC 回放，录到空的 BNC 口会立刻露馅 |
| 相机拍摄屏幕时的手抖特写 | —— |
